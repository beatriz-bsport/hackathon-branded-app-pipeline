## Overview

Tag input is the **pattern** for entering many labeled values — member tags, filter
tokens, email recipients — where each value appears as a [Chip](/components/chip).
Kaizen does not ship a dedicated `TagInput` primitive yet; compose with
[Autocomplete](/components/autocomplete) multi-select, [Chip list](/components/chip-list),
or [Dropdown multi select](/components/dropdown-multi-select) depending on density.

### Use cases

- **Member tags** — add existing or create tags on CDP profile.
- **Campaign audiences** — select multiple segments.
- **Filter tokens** — typeahead then chip appears in toolbar.
- **Email CC** — addresses as dismissible chips (with validation).
- **Admin labels** — color tags on buyables.

## Guidelines

<DoDont>
  <Do caption="Show each tag as a chip inside the input bounding box." />
  <Do caption="Debounce autocomplete search for large tag directories." />
  <Do caption="Confirm before creating new tags that affect billing or access control." />
  <Dont caption="Free-text comma lists without chips — hard to edit and error-prone." />
  <Dont caption="Hundreds of tags in one field — use multi-select modal." />
  <Dont caption="Tags without color or label distinction when categories differ." />
  <Do caption="Dismissible chips — removable tokens with `dismissible` Chip when editing." />
  <Do caption="Create vs select — distinguish picking existing tags from creating new ones in copy." />
  <Do caption="Validate on add — reject duplicates and invalid format before chip mounts." />
  <Do caption="Keyboard — Enter adds token; Backspace removes last chip when input empty." />
  <Do caption="Overflow — use Chip list when displaying many tags read-only." />
</DoDont>

### Props

Compose from Autocomplete `multi` mode and Chip props — no single PropsTable until primitive exists.

### Behaviors

#### Dismissal

Removing chip updates form array value immediately or on blur per form design.

### Edge cases

- **Duplicate tag** — block or merge silently with toast — pick one product rule.
- **Max tags** — enforce limit with helper text.

## Accessibility

### ARIA roles & attributes

Input needs label; chips in `list` with `aria-label` on container ("Selected tags").

### Screen reader behavior

Announce chip add/remove via polite live region when list changes.

### Focus management

Focus stays in input after adding chip.

### WCAG criteria

- **3.3.1 Error Identification** — invalid tag format described in text.
- **4.1.2 Name, Role, Value** — input labeled; chips identifiable.
