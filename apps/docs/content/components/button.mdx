## Overview

The Button is a core interactive primitive in Kaizen that triggers an action or
navigates the user to a new context. It appears in forms, modals, dialogs, and
throughout the Kaizen back-office interface to communicate available actions
clearly. Buttons communicate hierarchy through three intents — `call-to-action`,
`default`, and `flat` — and adapt to different tonal contexts via the `color`
and `intent` props.

### Use cases

- **Primary actions:** Use `intent="call-to-action"` with `color="main"` for
  the single most important action on a page or modal (e.g. "Save", "Confirm",
  "Create").
- **Secondary action:** Use `intent="default"` for supporting actions that sit
  alongside a primary button (e.g. "Cancel", "Edit").
- **Subtle / tertiary action:** Use `intent="flat"` for low-emphasis actions
  that should not compete visually with surrounding content (e.g. inline row
  actions, auxiliary links).
- **Destructive action:** Use `color="critical"` combined with any intent to
  signal an irreversible or destructive operation (e.g. "Delete member",
  "Remove plan").
- **Icon-only action:** Use `kind="icon-button"` with the `icon` prop when a
  label would create clutter in dense UIs like headers or table rows — always
  pair with a tooltip.

<DoDont>
  <Do caption="Use in tables and lists for row-level actions where density requires minimal visual weight." />

#### critical color

<DoDont>
  <Do caption="Combine with a confirmation modal or inline warning before the action executes." />

<DoDont>

#### Content

#### Common uses

**Form submission** — `intent="call-to-action"`, `color="main"`, `size="md"`,
`loading` bound to submit state.

> "Save changes"

**Destructive row action** — `intent="flat"`, `color="critical"`,
`iconLeft="trash-01"`.

> "Delete"

**Navigation to detail** — `intent="default"`, `iconRight="arrow-right"`,
`size="md"`.

> "View details"

**Cancel / dismiss** — `intent="default"`, `color="default"`, no icons.

> "Cancel"

#### Buttons vs. links

A button _does something_; a link _goes somewhere_. In certain circumstances, a
button can look like a button but behave like a link — for instance when updating
user data, saving edited content, or deep-linking to a dialog.

### Behavior

#### Loading state

When `loading=true`, the button renders a spinner in place of its content and
becomes non-interactive. Width and height are locked to pre-loading dimensions
to prevent layout shift. Remove the loading state once the async operation
completes or errors.

#### Disabled state

When `disabled=true`, the button is visually de-emphasized and does not respond
to pointer or keyboard events. Do not use disabled as a replacement for
conditional visibility — prefer hiding the action when it is permanently
unavailable in context.

#### Icon placement

`iconLeft` is preferred for icons that describe the action type (e.g. `plus`
before "Add member"). `iconRight` is preferred for directional or navigation
icons (e.g. `arrow-right`, `chevron-right`, `link-external-02`). Avoid using
both simultaneously unless both icons carry distinct meaning.

### Edge cases

#### Label is very long

The button stretches horizontally. Use `fullWidth` or constrain the container
width; never truncate the label.

#### Both iconLeft and iconRight set

Renders both icons flanking the label. Avoid this combination unless the icons
serve clearly distinct roles.

#### loading=true + disabled=true

Loading state takes visual precedence; the button remains non-interactive in
both cases.

#### kind="icon-button" + label prop

The `label` prop is ignored visually but should still be provided to enable
accessible aria-label derivation.

#### color="onstrong"

Intended for use only on strong-colored backgrounds.

#### color="selected"

Represents a toggled-on or active state. Use with ToggleButton patterns rather
than standalone actions.
