## Overview

Avatar group shows several people in a compact overlapping stack — class attendees,
assigned coaches, or collaborators. It displays up to three [Avatar](/components/avatar)
images, then a "+N" tile that opens a [Popover](/components/popover) menu listing the rest.

### Use cases

- **Session roster preview** — coaches and assistants on a class row.
- **Project collaborators** — shared admin resources with many assignees.
- **Attendance modal** — compact member stack before expanding full list.
- **Comment thread faces** — few recent authors with overflow.
- **List row compact mode** — alongside title in [List item](/components/list-item).

## Guidelines

- **Max three visible** — additional members appear only via +N popover.
- **Consistent size and shape** — match single Avatar rules (`round` for people).
- **Meaningful names in data** — `name` drives initials fallback and menu labels.
- **Cap overflow display** — shows up to 99 extra in the counter label.
- **Read-only stack** — avatars in group use `pointer-events-none`; navigate via popover items.

### Best practices

#### General

<DoDont>
  <Do caption="Pass stable id per avatar for keys and menu item identity." />
  <Do caption="Use round shape for people; squared only when matching product thumbnails." />

  <Dont caption="Avatar group as the only way to see full roster — link to full list." />
  <Dont caption="Single person — use Avatar alone without +0 overflow." />
  <Dont caption="Mixing photo and generic icons without names in popover." />

### Behaviors

#### Dismissal

Popover closes on outside click per Popover defaults.

#### Responsiveness

Negative margin overlap scales with `size` token.

### Edge cases

- **Fewer than four members** — no overflow tile; only avatars shown.
- **Missing src** — initials from `name` via getInitials helper.
- **More than 102 total** — counter caps display at +99 pattern.

## Accessibility

### ARIA roles & attributes

Overflow trigger needs accessible name ("4 more members"). Menu items should be focusable links or buttons.

### Keyboard navigation

<Accessibility
  keyboard={[
    { keys: ["Tab"], description: "Focuses overflow trigger when present." },
    {
      keys: ["Enter", "Space"],
      description: "Opens member menu from overflow.",
    },
  ]}
/>

### Screen reader behavior

Announce total count in overflow button label, not only "+4".

### Focus management

Popover traps focus while open; return to trigger on close.

### WCAG criteria

- **2.1.1 Keyboard** — reach overflow menu.
- **4.1.2 Name, Role, Value** — overflow button named with member context.
