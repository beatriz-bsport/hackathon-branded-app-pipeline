## Overview

Expandable content describes a **UX pattern**: primary information stays visible
while secondary detail expands on demand. In Studio Manager, implement it with
[Collapse](/components/collapse) or [Accordion](/components/accordion). Legacy
Fabric `ExpandableContent` still exists in saas-legacy marketplace cards — do
not use it for new SM features.

### Use cases

- **Pass card details** — show price and title collapsed; expand for full description.
- **FAQ blocks** — accordion sections on help content.
- **Advanced form fields** — "More options" collapse on create pass flows.
- **Invoice line items** — expand row for tax breakdown.
- **Filter help** — explain advanced filter semantics on demand.

## Guidelines

<DoDont>
  <Do caption="Keep the collapsed summary self-sufficient for the most common task." />
  <Do caption="Use Accordion when several independent sections expand on one page." />
  <Do caption="Preserve expanded state in URL hash when deep-linking to a section." />
  <Dont caption="Hiding legal or pricing terms required before purchase." />
  <Dont caption="Expandable content for critical errors — use Alert." />
  <Dont caption="New Studio Manager screens importing Fabric ExpandableContent." />
  <Do caption="Kaizen path — Collapse for single region; Accordion for multiple sections." />
  <Do caption="Clear trigger — button text states outcome (Show details / Hide details)." />
  <Dont caption="Do not hide required fields — required inputs stay visible or marked in header." />
  <Do caption="Legacy marketplace — Fabric ExpandableContent only in saas-legacy maintenance." />
  <Do caption="Animation — match Collapse ~200ms; avoid jarring height jumps." />
</DoDont>

### Props

Implement via Collapse or Accordion — see those component reference tabs.

### Behaviors

#### Dismissal

User toggles trigger; no auto-collapse on outside click unless custom logic added.

## Accessibility

### ARIA roles & attributes

Use Accordion's `ariaLabel` on items or wire `aria-expanded` on Collapse triggers.

### Keyboard navigation

<Accessibility
  keyboard={[
    {
      keys: ["Enter", "Space"],
      description: "Toggles expansion on button triggers.",
    },
  ]}
/>

### Screen reader behavior

Expanded state announced via `aria-expanded`.

### Focus management

Avoid focus inside collapsed hidden content.

### WCAG criteria

- **2.1.1 Keyboard** — operable triggers.
- **3.3.2 Labels or Instructions** — required fields not hidden without indication.
