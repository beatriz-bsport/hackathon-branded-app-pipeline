## Overview

RadioGroup renders a labelled set of radio options where only one can be
selected. Use it when every option should stay visible and the list is short
enough to scan — typically two to five choices. For longer lists or search, use
[Select](/components/select) or [Autocomplete](/components/autocomplete).

### Use cases

- **Delivery format** — email vs print vs in-person on gift card configuration.
- **Visibility scope** — public vs members-only vs staff-only on pass settings.
- **Payment timing** — charge now vs add to invoice on checkout sub-flows.
- **Conditional fields** — reveal extra inputs under the selected option via
  `children` on an option.
- **Required single choice** — gender or legal status when regulations require
  an explicit pick before submit.

## Guidelines

- **Always grouped** — never render a lone radio; a single visible option belongs
  in [Select](/components/select) or [Toggle](/components/toggle).
- **Mutually exclusive** — one `value` on the group; updating it clears the
  prior selection.
- **Short lists only** — beyond ~5 options, move to Select unless every label
  must stay visible for comparison.
- **Children for follow-ups** — nest related fields in `option.children`; they
  show when that option is selected (or always with `forceDisplayChildren`).
- **Per-option errors** — pass `errorText` on an option to highlight a specific
  row after validation.

### Behaviors

#### Selection

Controlled via `value` (selected option `value` string) and `onChange` (change
event on the underlying input). Parent updates `value` to move selection.

#### Children visibility

When `option.children` is set, it renders when `value === option.value` unless
`forceDisplayChildren` is true.

#### Persistence

Selection is controlled externally. Unmounting preserves whatever `value` the
parent passes on remount.

#### Responsiveness

Options stack in a vertical column (`flex-col gap-xs`). Long labels wrap within
the column width.

### Edge cases

#### Single option

Avoid — use Select or Toggle. Radio semantics imply a choice among alternatives.

#### All options disabled

Pass `disabled` on the group or per option. Provide `helperText` explaining why
choices are blocked.

#### Duplicate values

Each option `value` must be unique within the group or selection state collides.

## Accessibility

### ARIA roles & attributes

- **Group** — `<fieldset role=\"radiogroup\">` with group `id`.
- **Radio** — native `type=\"radio\"` per option with `aria-checked`.
- **Invalid** — `aria-invalid` when option `errorText` is set.
- **Label** — group label via `Label`; each option uses `<label htmlFor>`.

### Screen reader behavior

Announces group label, option labels, position in set, and selected state.
Helper and error text for the focused option are available in reading order.

### Focus management

Focus moves between radios with arrow keys inside the group. Children revealed
below an option are inserted in tab order after the option row.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — selected and error rings use token colours.
- **2.1.1 Keyboard** — full keyboard selection within the group.
- **4.1.2 Name, Role, Value** — group name from label; value from selected
  option.

#### Implementation gaps

- **Radio `name` attribute** — each `RadioButton` sets `name={value}` (unique per
  option) instead of a shared group name. Selection is driven by React `checked`
  state; native HTML grouping may not match expectations in uncontrolled usage.
