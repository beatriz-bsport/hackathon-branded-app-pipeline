## Overview

A non-modal slide-in surface for inspecting or lightly editing a selected record without leaving the list

DetailDrawer is a transient, side-mounted container that shifts focus to one object while you stay on the current page. It slides in from the right on desktop and from the bottom on viewports ≤1024px. There is no backdrop and no focus trap — the list or board beneath stays scrollable and interactive — so you can triage, preview, and run quick edits without losing filters, scroll position, or selection context.

### Use cases

- **List-item preview** — open a member, booking, or pass from a table to inspect metadata without navigating away from the list.
- **Triage and queue processing** — step through records with previous/next controls in `actionsConfig` while the drawer stays open.
- **Linked record peek** — preview a related contact or parent booking from inside another record so the operator keeps their place.
- **Quick edits** — change status, assign a tag, or toggle a setting scoped to one object (≤5 fields, under ~30 seconds).
- **Lightweight creation follow-up** — review a record immediately after a modal create flow without a full page transition.

## Guidelines

<DoDont>
  <Do caption="Open the drawer when operators browse a list or queue and need to peek at a record without losing scroll position or applied filters." />
  <Do caption="Wire previous and next navigation through actionsConfig whenever the drawer opens from a list so operators can triage without closing and reopening." />
  <Do caption="Highlight the row or card that opened the drawer so context stays visible behind the panel." />
  <Dont caption="Stacking drawers fragments context — replace the drawer body with a back affordance or navigate to a full page when opening a different record." />
  <Dont caption="Primary work destinations belong on a dedicated page, not in a drawer opened from a deep link or main navigation." />
  <Dont caption="Object creation and multi-step flows belong in Modal or on a page, not in DetailDrawer." />
  <Do caption="Choose the right surface — blocking decisions use `Modal`; persistent metadata on the current record uses `Panel`. See `Panel vs Drawer vs Modal` when unsure." />
</DoDont>

<Callout type="warning" title="Caution">

When operators routinely spend more than a minute inside the drawer, the object likely deserves a full page. Add a "View full page" affordance in the header rather than expanding the drawer's scope with tabs or nested navigation.

</Callout>

### Content rules

Keep copy concise and actionable. The drawer has no built-in title slot — compose a heading with [Title](/components/title) (`htmlVariant="h2"`) at the top of `children`.

**Drawer title** — name the open record.

> Jane Smith

**Section label** — step down inside the body.

> Contact details

**Quick-edit labels** — short field names, no trailing punctuation.

> Status

**Empty state** — never leave a blank body when data is loading or missing.

> Select a member to view details.

**Error state** — explain what failed and offer retry; do not close the drawer on load failure.

> Unable to load booking details. Check your connection and try again.

A quick edit is scoped to one object, involves at most five fields, completes in under thirty seconds, and does not change the object's core identity. Examples: change status, add a tag, assign an owner, toggle a setting, rename an item. Role changes, full profile edits, and multi-step wizards belong on a page or in a modal.

### Behaviors

#### Opening and closing

Visibility is controlled entirely by `isOpen`. On open, the drawer mounts and plays a CSS slide-in animation (right on desktop, bottom on tablet and mobile). On close, the exit animation runs for 300ms before unmount.

#### Dismissal

- **Close button** — fires `onClose`.
- **Escape** — fires `onClose` via `withEscapeHandler`.
- **Click outside** — not supported. The drawer is non-modal; clicks on the page behind do not close it.

The drawer does not confirm unsaved changes. Intercept `onClose` in the consuming feature when a dirty form needs a prompt.

#### Navigation controls

Pass previous and next handlers as entries in `actionsConfig`. Buttons render in the header trailing area with configurable tooltips. Keyboard shortcuts (e.g. j/k) are not built in — bind them at the page level if needed.

#### Persistence

The drawer does not survive route changes unless the parent keeps `isOpen` true. Content inside `children` is cached during the close animation only.

#### Responsiveness

At viewport widths ≤1024px (phones and tablets), the drawer uses bottom-sheet positioning (`h-[90vh]`, `max-h-screen`). Above that breakpoint it anchors to the right at full height with `min-w-[420px]`.

### Edge cases

- **Item deleted while drawer is open** — show a [Toast](/components/toast) confirming deletion and advance to the next list item if applicable.
- **Unsaved changes on close** — no built-in guard; the consumer intercepts `onClose` and shows a confirmation modal when needed.
- **Network error loading content** — render an error state inside the body with retry; keep the drawer open.
- **Drawer opened with no content** — show a meaningful empty state, never a blank panel.
- **Very long body content** — the body scrolls independently; keep sections short or add a link to the full page.
- **Panel open at the same time** — supported. The panel stays in its grid column; the drawer overlays above it.

## Accessibility

### ARIA roles & attributes

The root element is `<aside>` with:

- `role="complementary"` — non-modal side panel.
- `aria-modal="false"` — page content remains in the accessibility tree.
- `aria-label` — set from the `id` prop (`id || "Detail drawer"`). Pass a descriptive `id` so assistive tech announces meaningful context.

Kaizen does not set `aria-hidden` on close — the drawer unmounts after the exit animation instead.

Action buttons in `actionsConfig` are standard [Button](/components/button) controls and participate in normal tab order.

### Screen reader behavior

When the drawer opens, assistive tech reads the `aria-label` derived from `id`. Because the drawer is non-modal, content behind it stays reachable — do not rely on the drawer alone to hide sensitive information from the accessibility tree.

Compose visible headings inside `children` with [Title](/components/title) so rotor and heading navigation expose the record name.

### Focus management

Focus is not moved into the drawer on open and is not trapped. This matches the non-modal model — operators can interact with the list and the drawer interchangeably. On close, focus is not restored automatically; manage return focus in the consumer when keyboard users opened the drawer from a specific row.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — drawer surface uses elevated default tokens; ensure custom body content meets contrast on `bg-surface-default-elevated`.
- **2.1.1 Keyboard** — Escape closes; header buttons are keyboard-operable.
- **2.4.3 Focus Order** — DOM order follows header then body; no focus trap.
- **4.1.2 Name, Role, Value** — role and modal state are set; name comes from `id` / `aria-label`.

#### Tracked in Linear

- [KAI-648](https://linear.app/bsport/issue/KAI-648/detaildrawer-layout) — DetailDrawer layout (Triage).
- [KAI-293](https://linear.app/bsport/issue/KAI-293/detail-drawer-adjust-drawer-height-based-on-the-height-of-the-header) — Adjust drawer height based on the height of the header (Backlog).

#### Implementation gaps

- **`aria-label` from `id`** — the component uses the raw `id` string as `aria-label`, not a separate human-readable label prop. Consumers must choose descriptive ids or accept generic announcements.
- **Tablet uses bottom sheet** — viewports ≤1024px (including tablet landscape) slide from the bottom, not only phone widths.
- **Close control position** — the close button sits at inline-start in the header, not inline-end as some design sketches show.

#### Design or API debt

- **No built-in title or identity block** — header only exposes close and `actionsConfig`; record name and "View full page" live in consumer-composed `children`.
- **Stale source JSDoc** — component comments reference `onPrevious` / `onNext` props; the shipped API is `actionsConfig` only.
