## Overview

Divider is a purely visual separator — a horizontal or vertical rule between
blocks of content. It carries no semantics, actions, or labels. Use it when
whitespace alone does not make the boundary clear enough, such as between form
sections, sidebar groups, or toolbar clusters.

### Use cases

- **Form sections** — separate billing from contact fields on a settings page.
- **Sidebar groups** — mark the boundary before system links at the bottom.
- **Toolbar clusters** — vertical divider between filter chips and primary actions.
- **Card footers** — horizontal rule above secondary actions in a dense card.
- **Menu groups** — pair with [Menu](/components/menu) item dividers for visual rhythm.

## Guidelines

- **Whitespace first** — reach for spacing tokens before adding a line; dividers
  add visual noise when overused.
- **Orientation matches layout** — `horizontal` for stacked sections; `vertical`
  in toolbars and inline clusters.
- **Weight matches emphasis** — `extra-thin` for subtle separation; `regular`
  when the boundary must read clearly.
- **Not a heading** — dividers do not replace titles; always label sections with
  [Title](/components/title) or [Body](/components/body).
- **One role per line** — do not stack multiple dividers with only a few pixels
  between them.

### Best practices

#### General

  <Dont caption="Dividers between every list row belong in table styling, not repeated Divider instances." />

### Content rules

Divider has no text. Section titles and descriptions live in sibling components.

### Behaviors

#### Responsiveness

Horizontal dividers span the full width of their container. Vertical dividers
need a parent with defined height — `min-h-full` stretches within flex rows.

### Edge cases

- **Vertical divider in auto-height parent** — may collapse to zero height; set
  parent `align-stretch` or explicit min-height.
- **Multiple adjacent dividers** — redundant; consolidate into one rule with
  larger spacing.

## Accessibility

### ARIA roles & attributes

Divider renders as a `span` with `data-component="Kaizen-Divider"`. It is
decorative — no role, label, or live region.

### Screen reader behavior

Screen readers ignore decorative dividers. Section structure must come from
headings (`h1`–`h6`) or `aria-labelledby` on landmarks.

### Focus management

Not applicable — non-interactive.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — stroke uses `stroke-divider` token against surfaces.
- **4.1.2 Name, Role, Value** — not applicable for decorative separators.
