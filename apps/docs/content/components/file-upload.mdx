## Overview

File upload handles selecting files via browse or drag-and-drop, previewing images,
and tracking upload progress. Use it for pass covers, member documents, and import
templates — wire to your API layer for `autoUpload` or fully controlled flows.

### Use cases

- **Pass cover image** — single image with size/type validation.
- **Member document** — PDF upload in CDP compliance flows.
- **CSV import** — file pick before mapping step in import wizard.
- **Venue gallery** — multiple images with replace/remove.
- **Brand assets** — logo upload in studio settings.

## Guidelines

<DoDont>
  <Do caption="List accepted formats and max size before users browse." />
  <Do caption="Show upload progress or success when autoUpload is enabled." />
  <Do caption="Allow removing a file before form submit." />
  <Dont caption="Silent failure when file exceeds limit — always message." />
  <Dont caption="Drag-only upload without a visible browse button." />
  <Dont caption="Uploading sensitive files without encryption context in copy." />
  <Do caption="State file constraints — max size and MIME types in helper text." />
  <Do caption="Preview images — show `Media` thumbnail after select." />
  <Do caption="Error on reject — explain why a file failed validation." />
  <Do caption="Controlled for wizards — parent owns File object until submit." />

### Behaviors

#### Persistence

Controlled mode keeps File in parent state until cleared or uploaded.

#### Responsiveness

Drop zone stacks in narrow columns; maintain minimum touch height.

### Edge cases

- **Replace file** — clear previous selection when new file chosen.
- **Failed upload** — retain file for retry with error message.

## Accessibility

### ARIA roles & attributes

Browse uses native file input (often visually hidden) with associated label.

### Keyboard navigation

### Screen reader behavior

Announce file name after selection; progress updates via live region when uploading.

### Focus management

Focus returns to remove/retry actions after upload completes.

### WCAG criteria

- **2.1.1 Keyboard** — browse path without drag-only.
- **3.3.2 Labels or Instructions** — constraints stated upfront.
- **4.1.3 Status Messages** — upload result announced.
