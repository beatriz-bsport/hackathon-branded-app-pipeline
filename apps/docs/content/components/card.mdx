## Overview

Card is a bounded container that groups one concept's worth of content inside a
rounded surface. Set `actionable={false}` for structural grouping with a border;
set `actionable={true}` when the whole region is one click target and needs
rest, hover, pressed, and selected backdrop states. Card is a layout primitive —
it does not ship title slots, media presets, or actions. Compose
[Title](/components/title), [Body](/components/body), [Button](/components/button),
and other Kaizen components as children.

A card has to earn its place. When none of the rules in
[Using cards](/patterns/using-cards) apply, use spacing, a divider, or a heading
instead.

### Use cases

- **Selectable choice** — large-target plan or option picker with `actionable`,
  `elevated`, and `selected` (e.g. subscription plan comparison, booking-flow
  multi-session toggle).
- **Object / entity tile** — heterogeneous browse item where the whole card
  navigates to detail (e.g. explore links on the homepage, mobile session cards
  in booking).
- **Page-level content group** — static bordered region separating one logical
  block from several others on a settings or segment-filter page.
- **Embedded table or list** — `padding="none"` wrapper around a table that sits
  inside a layout rather than on a dedicated list page.
- **Promotional or empty-state block** — static card for informational nudges,
  or actionable when the entire surface is the CTA.

## Guidelines

- **Earn the boundary** — default to heading + spacing; reach for Card only when
  the border or backdrop adds meaning, affordance, or separation. See
  [Using cards](/patterns/using-cards).
- **Pick the variant by interaction** — `actionable={false}` for structural
  grouping; `actionable={true}` when the whole region is one click target.
- **Group siblings consistently** — cards in a grid should share the same
  variant; avoid mixing actionable and static neighbors in one row.
- **Compose, don't configure** — Card has no title, media, or footer slots;
  layout and content live in `children`.
- **Reserve elevation for actionable** — `elevated` only affects actionable
  cards; static cards always use the bordered elevated surface style.

### Behaviors

#### Persistence

Card is presentational — it survives re-renders and navigation as long as the
parent keeps it mounted. Selected state is controlled via the `selected` prop.

#### Responsiveness

Card does not change layout at breakpoints. Multi-column card grids should
collapse to a single column at narrow widths in the parent layout; below ~320px
wide, consider switching dense collections to a list pattern (see
[Using cards](/patterns/using-cards)).

### Edge cases

#### onClick without actionable

`onClick` is ignored when `actionable={false}` — the handler never runs.

#### selected without actionable

`selected` has no visual effect when `actionable={false}`; selected styling is
wired only to actionable variant tokens.

#### padding="none" with media or tables

Children extend to the card edge. Add `overflow-hidden` on the root via
`className` when rounded corners must clip inner content — the component does
not clip by default.

#### Multiple instances

Stack or grid sibling cards in the parent; Card does not coordinate selection
across a group — the parent owns which card has `selected={true}`.

## Accessibility

### ARIA roles & attributes

The root element is a `<div>` with `data-component="Kaizen-Card"`. Kaizen does
not set `role`, `tabIndex`, or `aria-*` attributes automatically.

- **Static cards** — treated as presentational grouping; expose structure through
  child headings and landmarks.
- **Actionable cards** — the root is clickable but not focusable by default;
  consumers must add keyboard support (see below).
- **Child controls** — buttons, links, and checkboxes inside the card keep their
  own roles; avoid duplicating the same action on both the root and a child.

For whole-card navigation or selection, prefer wrapping content in a `<button>`
or `<a>`, or render the card inside a focusable control with an accessible name.
The built-in `onClick` on a `<div>` is pointer-only.

### Screen reader behavior

Screen readers announce child content in document order. The card container
itself has no accessible name unless you provide one via a child heading or an
`aria-label` on the root.

Actionable cards do not announce selected state automatically — pair `selected`
with visible copy or `aria-pressed` / `aria-current` on a proper interactive
wrapper when the selection matters to assistive tech.

### Focus management

Card does not trap or move focus. When an actionable card navigates away, focus
behavior is owned by the destination route or overlay.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — static and actionable surfaces use design-system
  tokens; verify contrast when overriding backgrounds via `className`.
- **2.1.1 Keyboard** — default actionable pattern is not fully keyboard-operable;
  add a focusable wrapper or native control for whole-card actions.
- **2.4.6 Headings and Labels** — use child Title or heading elements so grouped
  content is programmatically discernible.
- **4.1.2 Name, Role, Value** — name comes from visible child text or an explicit
  label on an interactive wrapper; the default div root does not expose button
  semantics.
- **4.1.3 Status Messages** — not applicable; use [Alert](/components/alert) or
  [Toast](/components/toast) for system feedback.

### Known issues

#### Tracked in Linear

- [KAI-842](https://linear.app/bsport/issue/KAI-842) — Content overflow at rounded corners (Scoping).
- [KAI-637](https://linear.app/bsport/issue/KAI-637) — Selected actionable card adds a 2px border and shifts layout vs default (Backlog).
- [KAI-638](https://linear.app/bsport/issue/KAI-638) — Selected state for non-actionable static cards (Scoping).
- [KAI-584](https://linear.app/bsport/issue/KAI-584) — `weak` surface variant used in product but not exposed on Card (Scoping).
- [KAI-844](https://linear.app/bsport/issue/KAI-844) — No `disabled` prop or visual state for actionable cards (Triage).
- [KAI-845](https://linear.app/bsport/issue/KAI-845) — Actionable card root is not keyboard operable (Triage).
- [KAI-846](https://linear.app/bsport/issue/KAI-846) — Nested interactives inside actionable cards create overlapping click targets (Triage).

#### Implementation gaps

- **No overflow clipping** — `rounded-md` does not clip children; edge-to-edge
  media or tables can square off corners unless the consumer adds
  `overflow-hidden` (see KAI-842).
- **`selected` requires actionable** — static cards cannot show a selected border
  through props today (see KAI-638).

#### Design or API debt

- **Teams hardcode weak surfaces** — several apps pass custom `className`
  backgrounds instead of a first-class variant (tracked as KAI-584).
