## Overview

Label associates visible text with a form control via `htmlFor`. Use it on every
field unless the control is a standalone button with its own text. Most Kaizen
inputs embed a label — standalone `Label` is for custom layouts (for example
[Date picker](/components/date-picker) trigger wiring).

Cross-field label conventions live in
[Shared form guidelines](/components/shared-form-guidelines).

## Guidelines

<DoDont>
  <Do caption="`htmlFor` matches input `id` — one label per control id." />
  <Do caption="Use the same wording in validation errors as in the label." />
  <Do caption="Clickable — label click focuses the associated control." />
  <Dont caption="One label spanning multiple unrelated inputs." />
  <Dont caption="Use Label as static copy above buttons or chip rows — use Body instead." />
  <Dont caption="Use Label for page sections — use Title for sections, Label for fields." />
</DoDont>

## Reference

Native `<label>` — clicking focuses the associated control when `htmlFor` is set.

### Known issues

- Session form local label is not a native `<label>` — no `htmlFor`, no focus on click
- Some Date picker usages omit `htmlFor` and matching control `id`
- Radio and Checkbox group already accept `label` — avoid duplicate Label above the group
- [KAI-538](https://linear.app/bsport/issue/KAI-538/kz-component-label)
