## Overview

Nested sortable list supports reordering items across multiple grouped lists —
categories with children, nested playlists, or multi-column boards. Built for
admin configuration where hierarchy depth is shallow (typically one nest level).

### Use cases

- **Activity groups** — reorder groups and activities inside booking setup.
- **Nested FAQs** — sections with ordered questions (prefer [Accordion](/components/accordion) for read-only).
- **Multi-list admin** — move items between columns in configuration tools.
- **Pack bundles** — ordered sub-items inside a product group.
- **Template blocks** — grouped content blocks with inner order.

## Guidelines

- **Shallow nesting** — avoid deep trees; flatten IA when depth exceeds two levels.
- **Distinct group labels** — each sub-list needs a visible heading.
- **Cross-list moves** — confirm API supports parent change, not just index.
- **Performance** — extended stories show many lists; gate feature for large datasets.
- **Undo** — destructive reorder deserves toast with undo when feasible.

### Best practices

#### General

<DoDont>
  <Do caption="Explain in copy that dragging across groups changes category membership." />
  <Do caption="Collapse groups sparingly — hiding drag targets frustrates admins." />
  <Do caption="Validate order server-side and surface errors without silent revert." />
  <Dont caption="Nested sortable for member-facing navigation — too fragile." />
  <Dont caption="Identical group titles — users cannot predict drop targets." />
  <Dont caption="Mobile-first flows relying on precision drag between columns." />
</DoDont>

#### Persistence

### Edge cases

- **Extended mode** — many parallel lists; test scroll and hit targets.
- **Empty child list** — still provide valid drop zone.

## Accessibility

### ARIA roles & attributes

Each list region needs accessible name; drag handles labeled per item.

### Keyboard navigation

  keyboard={[

### Screen reader behavior

Cross-list moves should announce new group and index when keyboard alternatives exist.

### Focus management

Complex drag — document keyboard gaps in product QA.

### WCAG criteria

- **2.1.1 Keyboard** — known gap for pure drag; track improvement backlog.
- **4.1.2 Name, Role, Value** — group labels required.
