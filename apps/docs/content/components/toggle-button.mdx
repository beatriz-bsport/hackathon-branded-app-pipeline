## Overview

Toggle button looks like [Button](/components/button) but retains a pressed state
to show selection — view mode switches, formatting toggles, or toolbar filters.
Use [Segmented control](/components/segmented-control) when options are mutually
exclusive segments; use standalone toggle buttons for independent on-off tools.

### Use cases

- **List density** — compact vs comfortable row height toggle.
- **Map vs list** — view switcher on scheduling pages.
- **Pin sidebar** — persist navigation panel open state.
- **Show archived** — include inactive records in table.
- **Toolbar bold** — formatting in rich text toolbars (when exposed).

## Guidelines

- **Pressed state visible** — rely on token background, not color alone.
- **Icon + label** — icon-only toggles need `aria-pressed` and tooltip.
- **Controlled when synced** — parent owns state tied to URL or store.
- **Group related toggles** — use `role="group"` when multiple affect one view.
- **Not for form booleans** — long-lived settings use [Toggle](/components/toggle).

### Behaviors

#### Persistence

Pressed state follows controlled `pressed` prop or internal state until toggled.

### Edge cases

- **Disabled while pressed** — show pressed styling and explain disable reason nearby.
- **Exclusive group** — only one pressed; manage at parent like radio behavior.

## Accessibility

### ARIA roles & attributes

Use `aria-pressed="true|false"` on the button element.

### Screen reader behavior

Announces label and pressed state on focus.

### Focus management

Focus stays on control after toggle.

### WCAG criteria

- **2.1.1 Keyboard** — toggle without pointer.
- **4.1.2 Name, Role, Value** — pressed state programmatic.
