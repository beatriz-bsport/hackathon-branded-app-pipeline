## Overview

TextField collects one line of user input — names, search queries, amounts,
emails, and other typed values. It supports prefixes, suffixes, icons, clear
actions, and validation status. Use [Autocomplete](/components/autocomplete)
when the user picks from suggestions; use TextArea (primitive) for multi-line
copy.

### Use cases

- **Names and titles** — class name, staff display name, gift card title.
- **Search** — `type=\"search\"` in toolbars and filter rows (hides native clear
  buttons for consistent styling).
- **Typed formats** — `email`, `tel`, `url`, `date`, `time`, `number` with
  browser validation hints.
- **Amounts and codes** — price or discount fields with prefix/suffix (`€`, `%`).
- **Sensitive values** — `password` fields with masked input.

## Guidelines

- **Labels always** — pass `label` and matching `id`; placeholders supplement,
  never replace labels.
- **Errors on interaction** — set `status=\"error\"` and `statusText` after blur
  or submit, not on initial render.
- **Full width in forms** — `fullWidth` in column layouts; default max width in
  compact toolbars.
- **Right type** — use native `type` for format hints; still validate on the
  server.
- **Clear affordance** — provide `onClear` when a filled search field should
  reset the list.

### Content rules

**Placeholder**

**Helper**

**Error**

> Reference must be at least 6 characters.

### Input types

Set `type` to match the data you collect. Browser validation and keyboards adapt
per type; always validate on the server too.

- **`text`** — short free text (names, titles, references).
- **`password`** — masked entry for secrets; pair with `autocomplete` where
  password managers apply.
- **`number`** — numeric values; optional `min`, `max`, and `step`.
- **`email`** — email-shaped input with mobile email keyboard hints.
- **`tel`** — telephone numbers; format in helper text or `statusText` on error.
- **`date`** — date values; native picker where supported, typed entry elsewhere.
- **`datetime-local`** — combined date and time in one control.
- **`time`** — time-of-day values.
- **`search`** — toolbar or filter queries; native clear button hidden — use
  `onClear`.
- **`color`** — hex colour entry with swatch UI; prefer dedicated colour
  pickers for complex flows.

For multi-line copy, use **TextArea** instead of stretching TextField.

### Behaviors

#### Focus and clear

Focus ring appears on the container when the input is focused (`shadow-focused`).
`onClear` wipes the value and should reset parent state.

#### Status

`status`: `default` | `positive` | `error`. Error uses critical border; positive
uses positive border. `statusText` renders below with matching colour.

#### Responsiveness

Without `fullWidth`, max width is `max-w-element-4xl`. With `fullWidth`, the
field stretches to the parent column.

### Edge cases

#### type color

Colour picker uses a split text + swatch UI with hex validation — prefer the
dedicated colour patterns in product flows when possible.

#### type search

Native browser clear buttons are hidden via CSS; use `onClear` for explicit reset.

#### Very long values

Input uses `text-ellipsis` — for long free text use TextArea.

## Accessibility

### ARIA roles & attributes

- Native text input with implicit role.
- `aria-invalid` when `status=\"error\"` and `statusText` is set.
- Label association via `Label` + `htmlFor` / `id`.
- `autocomplete` prop forwards to the native attribute for password managers.

### Screen reader behavior

Announces label, required, placeholder, and value. Error `statusText` is read
when present in the DOM below the field.

### Focus management

Use `inputRef` to focus on mount in modals. Clear button should be keyboard
reachable when implemented via `onClear`.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — text, border, and error colours on default surfaces.
- **2.1.1 Keyboard** — fully keyboard operable.
- **3.3.1 Error Identification** — errors described in `statusText`.
- **4.1.2 Name, Role, Value** — name from label; value from input.
