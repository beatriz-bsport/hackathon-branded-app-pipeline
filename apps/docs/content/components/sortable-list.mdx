## Overview

Sortable list extends [List](/components/list) with drag handles to reorder items —
playlist order, menu ordering, featured products, or workflow step priority. Persist
order to the API on drop or via explicit save depending on product rules.

### Use cases

- **Featured passes** — studio-controlled order on marketplace.
- **Custom field order** — arrange member profile fields.
- **Email block order** — marketing template sections.
- **Category ordering** — booking activity display sequence.
- **Form wizard steps** — admin-defined step order (with validation).

## Guidelines

<DoDont>
  <Do caption="Show drag handle only when user has permission to reorder." />
  <Do caption="Optimistically update UI then rollback API failure with toast." />
  <Do caption="Use with clear page title explaining order affects member-facing UI." />
  <Dont caption="Sortable rows mixed with non-sortable without visual distinction." />
  <Dont caption="Drag reorder on paginated data without loading full set." />
  <Dont caption="Relying on drag alone for accessibility — offer move buttons." />
  <Do caption="Handle affordance — drag handle icon visible; do not drag entire row without cue." />
  <Do caption="Save strategy — auto-save on drop vs Save button — pick one per flow." />
  <Do caption="Disable sort when filtered — reordering filtered subsets misleads users." />
  <Do caption="Keyboard alternative — provide move up/down actions when possible." />
  <Do caption="Limit list length — very long lists need virtualisation review before enabling drag." />
</DoDont>

### Content rules

Helper text when order matters:

> Drag to change the order members see on the app home screen.

### Behaviors

#### Persistence

Order updates in parent `items` array on drag end; persist via mutation.

### Edge cases

- **Duplicate ids** — break drag logic; enforce unique ids.
- **Concurrent editors** — refresh order from server on conflict.

## Accessibility

### ARIA roles & attributes

Drag handles need `aria-label` ("Reorder item"); use live region to announce new position when keyboard alternatives exist.

### Screen reader behavior

Announce position change after drop when polite live region is wired.

### Focus management

Retain focus on moved item after keyboard reorder when supported.

### WCAG criteria

- **2.1.1 Keyboard** — provide non-drag reorder path where required.
- **4.1.2 Name, Role, Value** — handle labeled.
