## Overview

Select replaces native `<select>` with a styled trigger and popover menu. It
supports grouping, icons, loading, and form submission via a hidden `name` input.
Use it for short to medium lists where search is unnecessary. For searchable or
multi-select lists, use [Autocomplete](/components/autocomplete).

### Use cases

- **Form enums** — sport type, country, VAT rate on studio settings.
- **Settings panels** — language, timezone, or template pickers in configuration
  sections with a small fixed set of options.
- **Linked fields** — picking a category filters a dependent field on the same
  page.
- **Compact toolbars** — `size=\"sm\"` variant in filter rows.
- **Grouped options** — section titles and dividers between related items.
- **Loading lists** — `loadingProps` while options fetch from the API.

## Guidelines

- **Label every field** — pass `label` so trigger and popover have context.
- **Group long lists** — use title and divider items past ~20 options.
- **Validate late** — `status=\"critical\"` and `errorText` after interaction or
  submit.
- **Binary choices** — two options often fit [Toggle](/components/toggle) or
  [Radio](/components/radio) better than a dropdown.
- **Width** — `fullWidth` in form columns; natural width in toolbars.

### Behaviors

#### Opening and closing

Opens on trigger click or `Enter` / `Space` when focused. Closes on selection,
`Escape`, or focus leaving the component.

#### Selection

Controlled: parent owns `value` and updates on `onChange(id)`. Uncontrolled:
`defaultValue` seeds internal state.

#### Responsiveness

`fullWidth` expands the trigger to the container width and sizes the popover to
match the trigger. `popoverPlacement` repositions near viewport edges.

### Edge cases

#### No items

Popover opens empty — always supply at least one selectable option.

#### All items disabled

Popover opens but nothing is selectable; explain via `helperText`.

#### Loading

`loadingProps.isLoading` shows a loader in the popover; keep the trigger enabled
only if retry is possible.

## Accessibility

### ARIA roles & attributes

- Trigger is a `<button type=\"button\">` — does not submit parent forms.
- Associate the trigger with `label` via visible label text (ensure `id` on
  trigger for `htmlFor` when using Label patterns).
- `errorText` with `status=\"critical\"` should be exposed to assistive tech as
  descriptive text below the trigger.

### Screen reader behavior

Announces label, trigger value, and expanded/collapsed state via button semantics.
Menu items follow Menu component announcements.

### Focus management

Focus returns to the trigger when the popover closes after selection. Escape
closes without moving selection.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — trigger and critical border tokens.
- **2.1.1 Keyboard** — open, navigate, and select without pointer.
- **4.1.2 Name, Role, Value** — name from label; value from trigger text.

### Known issues

#### Tracked in Linear

- [KAI-843](https://linear.app/bsport/issue/KAI-843/select-show-the-right-slot-on-the-collapsed-trigger) — Show the right slot on the collapsed trigger (QA/ Dev review).

#### Design or API debt

- **Trigger prefix / suffix** — Supernova specifies inline prefix/suffix on the
  collapsed trigger (e.g. `€` before amount, `kg` after). Not implemented; use
  `iconLeft` or weave units into option labels until the API ships.
- **`controlledLabel` pattern** — long option labels vs short trigger labels
  discussed in [KAI-194](https://linear.app/bsport/issue/KAI-194); not yet a
  public prop.
