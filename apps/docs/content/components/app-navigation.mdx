## Overview

Studio Manager uses a **two-layer navigation shell**. The left sidebar answers _"Where can I go in the Back Office?"_ The page header answers _"What can I do inside this module?"_ Each layer has a distinct job — mixing them breaks spatial memory.

```text
┌─────────────┬──────────────────────────────────────────────┐
│   SIDEBAR   │  PAGE HEADER (feature-internal)              │
│   global    │  breadcrumbs · title · tabs · actions        │
│   modules   ├──────────────────────────────────────────────┤
│             │  page content                                │
└─────────────┴──────────────────────────────────────────────┘
```

Kaizen provides **`Sidebar`** and **`NavigationMenu`** for the global rail. Feature-internal navigation is composed from **[Header layout](/components/header-layout)**, **[Tabs](/components/tabs)**, and **[Breadcrumbs](/components/breadcrumbs)** — there is no separate top-bar navigation primitive.

### Global layer — Sidebar and NavigationMenu

**Sidebar** is the persistent left rail: brand, module links, global utilities, and account actions. On mobile it collapses into a drawer with a toggle in the top bar.

**NavigationMenu** is the structured menu inside the sidebar — items, groups, dividers, and expandable sub-items with icons and badges. In Studio Manager, the navigation-sidebar app composes `Sidebar` + `NavigationMenu` for all global wayfinding.

**Typical global destinations**

- Feature modules — Scheduling, Members, Finance, Marketing
- Cross-cutting tools — global search, notifications
- Quick actions — add member, create sale (where product allows)
- System utilities — settings, help, account, logout (grouped at the bottom)

### Feature layer — page header

The header region is scoped to the active sidebar module. It updates when the user switches modules. Use it for sub-routes, contextual actions, and nested hierarchy — not for global destinations.

**Typical feature-internal content**

- Sub-feature tabs — Invoices, Payouts, Settings within Financial Services
- Contextual actions — Add member, Export CSV, Apply filters
- Breadcrumbs — nested pages under the active tab
- Page title and status badges — current view identity

Compose this layer with **HeaderLayout** or **DetailsLayout** and route-level **Tabs**. See [Header layout](/components/header-layout) and [Tabs](/components/tabs) for API and examples.

### NavigationMenu

NavigationMenu is a composable vertical menu: items with optional sub-items, groups, dividers, icons, and trailing slots (badges, indicators). It is designed for sidebars and other hierarchical lists — not for horizontal page tabs.

## Guidelines

### Shell contract

<DoDont>
  <Do caption="One destination, one layer — if Members is a sidebar module, its sub-sections (Profiles, Tags…) live only in the page header, not repeated in both rails." />
  <Do caption="Sidebar owns global scope — module switching, search, notifications, account, logout." />
  <Do caption="Header owns feature scope — tabs, breadcrumbs, and actions tied to the current module." />
  <Do caption="Shallow sidebar depth — prefer expandable sub-items over deep flyouts; reserve multi-tab flows for the header." />
  <Do caption="Active states follow the router — highlight the current module in the sidebar and the current sub-route in tabs." />
</DoDont>

<Callout type="warning" title="Caution">

Duplicating hierarchy in both sidebar and header fragments wayfinding. Each destination should live in exactly one layer.

</Callout>

### Sidebar

<DoDont>
  <Do caption="Keep high-traffic modules in the primary stack with stable icons and labels." />
  <Do caption="De-emphasize settings and logout in a bottom group separated by spacing." />
  <Do caption="Show active state on the current module even when a child route is open." />
  <Dont caption="Deep flyout trees in the sidebar — use the page header for sub-features." />
  <Dont caption="Feature-specific filters in the global sidebar." />
  <Dont caption="Hiding logout or account behind undocumented gestures." />
</DoDont>

Module labels use product terms users recognize:

> Scheduling

> Members

### Feature header

<DoDont>
  <Do caption="Update tabs when the router active module changes." />
  <Do caption="Keep tab count manageable — split into settings pages when more than six." />
  <Do caption="Place module-specific actions in the header action cluster." />
  <Dont caption="Global settings or logout in feature header actions." />
  <Dont caption="Deep multi-level menus in the header — use the sidebar for modules." />
  <Dont caption="Tabs that navigate away from the module without clear labeling." />
</DoDont>

Tab labels match route purpose:

> Invoices

> Payout settings

### NavigationMenu

<DoDont>
  <Do caption="Use groups and dividers to separate modules from utilities." />
  <Do caption="Omit permission-gated items entirely rather than showing disabled dead ends." />
  <Do caption="Pair trailing badges or indicators with a clear menu label." />
  <Dont caption="Horizontal tab switching — use Tabs in the page header instead." />
  <Dont caption="More than one expanded sub-menu open at a time without a clear reason." />
  <Dont caption="NavigationMenu as a substitute for Sidebar on desktop — wrap it in Sidebar for shell behavior." />
</DoDont>

### Behaviors

#### Sidebar responsiveness

Collapses to a mobile drawer below the `md` breakpoint. Desktop rail stays fixed; mobile overlay traps focus until dismissed.

#### Sidebar persistence

Active module follows router state. Collapse preference may persist per user where the host app implements it.

#### NavigationMenu selection

Active item and sub-item follow click handlers and host routing. Sub-items expand under their parent item.

#### Feature header persistence

Active tab follows the URL. Survives refresh when routes are URL-driven.

### Edge cases

- **Single sub-route** — hide the tab bar when only one child route exists.
- **Permission-gated tabs or modules** — omit unauthorized routes entirely.
- **Federated modules** — show loading state while remote nav chunks load.
- **Sidebar with one module** — still render the rail for utilities; do not move global actions into the header.

## Accessibility

### Landmarks and roles

- **Sidebar** — `aside` with `role="navigation"` and an accessible label (defaults via i18n).
- **NavigationMenu** — list of links inside the sidebar landmark; current page uses `aria-current="page"` where the host sets it.
- **Feature header** — `nav` for tab lists; breadcrumbs use the Breadcrumbs component landmark pattern.

### Screen reader behavior

Announce module and tab names with current state. Skip redundant unlabeled logo links. For notification counts in `endSlot`, ensure the visible menu label plus count pill form a coherent phrase.

### Focus management

Route changes in Studio Manager should move focus to the page `h1` per shell convention. Mobile sidebar open traps focus in the overlay until closed.

### WCAG criteria

- **2.4.1 Bypass Blocks** — skip link to main content alongside the sidebar.
- **2.4.8 Location** — active module and tab indicate place within the product.
- **4.1.2 Name, Role, Value** — link and tab names match destinations.

### Known issues

<Callout type="info">

The feature-internal layer is a **composition pattern** (HeaderLayout + Tabs), not a single Kaizen export. Studio Manager host and federated apps wire it per module.

</Callout>

#### Implementation gaps

- **NavigationMenu placement** — NavigationMenu ships as a vertical menu and is composed inside Sidebar in production; horizontal page tabs use Tabs + HeaderLayout, not NavigationMenu.
- **Sidebar collapse breakpoints** — responsive icon-only mode and tooltip behavior are not yet fully specified in design tokens.
