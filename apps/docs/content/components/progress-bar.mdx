## Overview

Progress bar visualizes completion from 0 to 100 when you know how far an operation
has advanced. In Kaizen it is exported as a primitive, but **product code does not
import it directly today** — it is rendered internally by [File upload](/components/file-upload)
during `autoUpload` flows (`LoaderProgressBar`).

Use [Loader](/components/loader) when duration is unknown. Reach for Progress bar
only when you need a standalone determinate indicator outside File upload.

### Use cases

- **File upload** — byte progress, success, and error states inside [File upload](/components/file-upload) (the only current Studio Manager usage).
- **Custom long-running jobs** — rare standalone use when a parent owns polling and can supply a 0–100 `value` (no product examples in Studio Manager yet).

<Callout type="warning" title="Prefer File upload">

For file transfers, use [File upload](/components/file-upload) with `autoUpload` —
it wires Progress bar, abort/retry actions, and i18n status copy for you.

</Callout>

## Guidelines

- **Prefer File upload** — do not duplicate upload progress UI; the primitive is already composed there.
- **Clamp values** — component clamps to 0–100; pass accurate percentages from the job or request.
- **Status matches outcome** — `main` while in progress, `positive` on success, `critical` on failure.
- **Size** — File upload uses `sm`; use `md` or `lg` only when the bar is a focal element.
- **Label and message** — file name as `label`, status line as `message` (see File upload pattern).

### Best practices

#### General

<DoDont>
  <Do caption="Drive value from real job or upload progress, not fake timers." />
  <Do caption="Switch to positive or critical status when the job finishes." />
  <Do caption="Use File upload for file transfers instead of wiring Progress bar yourself." />
  <Dont caption="Indeterminate waits belong in Loader, not a stuck 0% bar." />
  <Dont caption="Importing Progress bar when File upload already covers the flow." />
  <Dont caption="Multiple bars for the same job in header and body." />
</DoDont>

### Behaviors

#### Responsiveness

Bar is full width of container; height from `size` token (`sm`, `md`, `lg`).

#### Animation

Fill width transitions with `duration-extra-long` when `value` updates.

### Edge cases

- **value 0** — empty fill; pair with a message when work has not started.
- **value over 100** — clamped to 100.
- **Missing label** — acceptable when adjacent copy explains context.

## Accessibility

### ARIA roles & attributes

The track element exposes `role="progressbar"` with `aria-valuenow`, `aria-valuemin={0}`,
`aria-valuemax={100}`, `aria-valuetext`, and `aria-label` derived from the current value.

### Screen reader behavior

Value is exposed on the track element. For fast polling, consider wrapping the region
in `aria-live="polite"` at the parent level — File upload handles this in its loading row.

### Focus management

Not applicable for static display.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — fill vs track uses status weak/strong surface pairs.
- **4.1.2 Name, Role, Value** — value exposed via progressbar semantics on the track.
