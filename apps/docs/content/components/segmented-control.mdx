## Overview

Segmented control lets users pick one option from a small, equally weighted set
and updates the content below without leaving the current page. It behaves like
radio buttons with a pill layout — ideal for second-level switching inside a
panel, drawer, or card. Use [Tabs](/components/tabs) when each option is a
different route or URL.

### Use cases

- **Inline list filters** — switch between _Past_ and _Upcoming_ sessions on the
  same list without changing the page route.
- **View modes** — toggle _List_ / _Grid_ on a catalog or member table while
  staying on the same screen.
- **Drawer sub-views** — move between _Tagged_ and _Untagged_ members inside a
  detail drawer.
- **Time granularity** — pick _Day_ / _Week_ / _Month_ on a calendar or
  analytics block scoped to one object.
- **Status slices** — filter transactional notifications or inbox items by _All_
  / _Active_ / _Archived_ when each slice updates inline content.

## Guidelines

- **Local context** — reserve segmented control for mutually exclusive views
  scoped to one object or surface; route-level navigation belongs on Tabs.
- **Small option sets** — aim for 2–5 segments; beyond six options the layout
  clutters and [Select](/components/select) reads better.
- **Equal weight** — every option should be a peer alternative, not a primary
  action; system-wide actions belong on Button or a toolbar.
- **Single selection** — one active segment at a time; multi-select patterns
  belong on [Checkbox group](/components/checkbox-group).
- **Compact copy** — keep labels short (one to three words) so segments stay
  scannable in drawers and cards.
- **Badges for counts** — pass `badge` on an option when a tally helps the
  choice (e.g. unread count); avoid badges on every segment when only one count
  matters.

### Best practices

#### General

  <Do caption="Switch content in place below the control — the page title and breadcrumbs stay the same." />
  <Do caption="Use parallel labels with the same grammar across segments — all nouns or all short verbs." />
  <Do caption="Disable individual segments when an option is temporarily unavailable, with context nearby if the reason is not obvious." />
  <Dont caption="Route-level navigation between peer pages belongs on Tabs — segmented control does not replace URL-based section switching." />
  <Dont caption="More than six options crowd the bar — a Select dropdown scales better for long enumerations." />
  <Dont caption="Mixing labeled and icon-only segments in one control breaks scan rhythm — pick one pattern per control." />
</DoDont>

<Callout type="warning" title="Caution">

Optional `urlQueryParamName` syncs the selection to a query parameter for
shareable filter state. Use it when bookmarking or back/forward should restore a
view — not as a substitute for Tabs or primary app navigation. For switching
inside a drawer or modal, keep selection in local state.

</Callout>

#### fullWidth

<DoDont>
  <Do caption="Stretch segments evenly when the control spans a toolbar or card header and each label is similarly short." />
  <Dont caption="Full width with long labels forces truncation — shorten copy or drop fullWidth so each segment sizes to content." />
</DoDont>

#### Icon-only options

<DoDont>
  <Do caption="Provide a `label` on every option even when only the icon shows — it becomes the accessible name." />
  <Dont caption="Icon-only segments without labels leave screen readers with generic 'Option {value}' fallbacks." />
</DoDont>

**SegmentedOption** (each entry in `options`):

- **`value`** (`string`, required) — unique identifier for the segment.
- **`label`** (`string`) — visible text; also used as the segment's accessible
  name.
- **`icon`** (`IconName`) — optional icon before the label.
- **`badge`** (`BadgeProps`) — optional count or status badge beside the label.
- **`disabled`** (`boolean`) — disables this segment only.

### Behaviors

#### Selection

Clicking a segment selects it and calls `onChangeValue` with its `value`.
Controlled parents pass `value`; uncontrolled usage relies on `defaultValue` and
internal state. Disabled segments and a disabled control ignore clicks.

#### URL synchronization

When `urlQueryParamName` is set, the component reads the matching query value on
mount, updates the URL on each selection without a full reload, and listens for
`popstate` so back/forward restore a valid option. On unmount it removes its
query parameter from the URL. Omit `urlQueryParamName` for purely local state
(e.g. inside drawers).

#### Responsiveness

With `fullWidth={false}`, segments size to content up to `max-w-[140px]`; long
labels truncate with ellipsis. With `fullWidth={true}`, segments share the row
evenly — best when labels are short and the bar spans the container.

### Edge cases

#### Fewer than two options

Console warns; the control still renders but does not meet the intended pattern.

#### More than six options

Console suggests Select — layout and scan cost grow quickly.

#### Invalid URL query value

Ignored; selection falls back to `defaultValue` or the first option.

#### Icon-only segment

Renders without visible text; `label` should still be provided for
`aria-label`. Without it, the fallback is `Option {value}`.

#### All segments disabled

Prefer `disabled` on the whole control instead of disabling every option
individually.

## Accessibility

### ARIA roles & attributes

- **`role="radiogroup"`** on the container — groups related segments.
- **`role="radio"`** on each segment — single-select semantics.
- **`aria-checked`** — `true` on the active segment, `false` on others.
- **`aria-label`** — on the radiogroup from the `label` prop; required when no
  visible group label is present.
- **Per-segment `aria-label`** — from `option.label`, or `Option {value}` when
  label is omitted.

Disabled segments are skipped when moving with arrow keys. Click still works for
pointer users on enabled segments.

### Screen reader behavior

Announces the group label (when provided) and each segment as a radio button
with its checked state. Selection changes update `aria-checked` on the affected
segments. Badge text inside a segment is exposed as part of the segment content.

### Focus management

Focus stays on the segment the user activated. Arrow-key navigation moves focus
to the newly selected segment. Focus is not trapped — users tab into and out of
the control freely.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — active and inactive segment text and surfaces
  use on-surface and action tokens.
- **2.1.1 Keyboard** — operable with Tab and arrow keys; Home and End jump to
  ends of the set.
- **4.1.2 Name, Role, Value** — radiogroup and radio roles with checked state;
  names from `label` and option labels.

### Known issues

#### Implementation gaps

- **Design vs URL sync** — product guidance treats segmented control as a local
  view switcher; the component optionally writes query parameters via
  `urlQueryParamName`. Docs recommend local state for drawers; URL sync only
  when shareable page state is intentional.
- **Container `disabled` styling** — `disabled` blocks interaction on segments
  but does not apply the container-level disabled variant from the style
  definition (opacity / pointer-events on the track).
- **Unmount clears query param** — leaving a page removes the control's query
  parameter on unmount, which can surprise deep-link flows.
- **Roving tabindex** — every enabled segment uses `tabIndex={0}`; a single
  tab stop with arrow-key roving focus inside the group would better match
  radiogroup keyboard patterns.
