## Overview

Avatar represents a person, member, coach, or account in a compact visual slot.
It shows a photo when `src` is available, falls back to initials or an icon, and
can open a profile or picker when you pass `onClick`. Avatars appear in lists,
headers, menus, and assignment fields across Studio Manager.

### Use cases

- **Member rows** — show the member photo or initials beside name in CDP lists.
- **Account menu** — render the signed-in user.
- **Picker targets** — use `onClick` to open a member or staff selector modal.
- **Stacked groups** — pair with [Avatar group](/components/avatar-group) when
  several people share one row.

## Guidelines

<Callout type="warning" title="Caution">

Avatar does not yet ship a built-in status badge. Wrapping with Indicator works
for dot counts, but overlapping badges on the avatar itself need design review.

</Callout>

<DoDont>
  <Do caption="Use initials derived from the display name when no image is available." />
  <Do caption="Match size to the list density — sm in tables, md in standard list rows." />
  <Dont caption="Generic placeholder icons without context read as broken data — prefer initials." />
  <Dont caption="Clickable avatars without a visible hover state confuse users — pair onClick with cursor and border feedback." />
  <Dont caption="Oversized avatars in dense tables steal scan focus from the primary column." />
  <Do caption="Image first — pass `src` and meaningful `alt` when a photo exists; initials are the fallback, not the default for known members." />
  <Do caption="Shape signals context — `round` for people; `squared` when aligning with cards or product thumbnails." />
  <Do caption="Click only when actionable — add `onClick` when the avatar opens a profile or selector; static rows should omit it." />
  <Do caption="Pair status elsewhere — use `Indicator` or `Badge` beside the row until native avatar status ships." />
</DoDont>

### Behaviors

#### Action button

`onClick` fires when the user activates the avatar container. Use for profile
navigation or opening a picker — not for unrelated row selection.

#### Responsiveness

Size tokens are fixed per variant; the parent layout controls alignment. In
narrow columns, prefer `sm` or `xs` and truncate the adjacent name instead of
shrinking the avatar below token sizes.

### Edge cases

- **Missing src and initials** — icon or children content renders; empty shells
  should be avoided in product UI.
- **Broken image URL** — browser shows broken image state; validate URLs upstream
  or fall back to initials.
- **onClick without keyboard** — the root is a `div`, not a button; wrap in a
  focusable control when keyboard access is required.

## Accessibility

### ARIA roles & attributes

The root is a `div` with `data-component="Kaizen-Avatar"`. No role is set by
default. When `src` is present, the inner `img` should carry `alt` from props.

### Screen reader behavior

Photo avatars announce `alt` text. Initials and icons are static text or
decorative depending on surrounding labels — ensure the adjacent name is in the
accessibility tree.

### Focus management

Focus stays on a parent interactive wrapper when you add one. The avatar itself
does not receive focus by default.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — initials and icons on default surfaces meet token contrast.
- **2.1.1 Keyboard** — provide a button wrapper when `onClick` is used.
- **4.1.2 Name, Role, Value** — meaningful `alt` or adjacent visible name.
