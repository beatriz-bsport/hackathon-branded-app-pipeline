## Overview

Toggle switches a boolean setting the moment the user flips it — the parent
handles `onToggleChange` and typically persists or applies the new state right
away. Use it for live preferences (notifications, feature flags on a detail
page). Use [Checkbox](/components/checkbox) when the user must confirm with
Save or Submit.

### Use cases

- **Feature enablement** — turn Wellpass or a partnership aggregator on for a
  session; saves on toggle via API.
- **Notification preferences** — email vs SMS channel switches on staff settings.
- **Visibility gates** — show optional sub-fields when "Custom schedule" is on.
- **Access control** — enable door access for a member pass without a modal
  confirm step.
- **Inline list filters** — quick active/inactive filters where the list updates
  immediately.

## Guidelines

- **Immediate effect** — wire `onToggleChange` to persist or update UI state;
  do not wait for a form footer.
- **Sensible default** — set `checked` to the state users expect in production
  so most sessions need zero toggles.
- **Positive labels** — describe what is on when checked: "Online booking
  enabled", not "Disable online booking".
- **Nested fields** — indent related inputs below an enabled toggle; align
  spacing with surrounding form sections until a shared indent token ships.
- **Not for submit forms** — legal consent and invoice options that need Confirm
  belong on Checkbox.
- **Error sparingly** — toggles rarely fail validation; use `errorText` only when
  the server rejects the last toggle attempt.

### Best practices

#### General

<DoDont>
  <Do caption="Label what is on when checked — 'Auto-renew membership' — and persist in onToggleChange." />
  <Do caption="Disable the toggle when the user lacks permission, with helper text explaining why." />
  <Do caption="Show dependent fields only when checked, indented under the toggle row." />
  <Dont caption="Modals that still need Save work better with Checkbox — Toggle implies immediate persistence." />
  <Dont caption="Many toggles without section headings blur related settings — group them with headings or spacing." />
  <Dont caption="When the API fails, revert checked and surface errorText or a toast so the flip does not feel successful." />
</DoDont>

<Callout type="warning" title="Caution">

Avoid vague labels like "Enable" without naming the setting — pair the verb with
the feature: "Online booking", "SMS reminders".

</Callout>

### Content rules

Labels are short, active phrases in sentence case.

> Send booking reminders

> Allow waitlist signups

Helper when the effect is non-obvious:

> Members can join when the class is full.

Error when save fails:

> Could not update this setting. Try again.

### Behaviors

#### Toggle action

`onToggleChange(boolean)` fires on each flip. Parent owns `checked` and updates
it after a successful save (or optimistically with rollback on failure).

#### Persistence

Controlled component — no internal checked state beyond the native input mirror.

#### Responsiveness

`direction=\"end\"` places the track on the right for dense settings rows.

### Edge cases

#### Failed save

If the API errors, set `checked` back to the prior value and surface
`errorText` or a [Toast](/components/toast).

#### Disabled mid-request

Disable while a save is in flight to prevent double toggles.

#### Missing label

`label` is required in the type definition — always provide one for a11y.

## Accessibility

### ARIA roles & attributes

- **Implementation note** — uses `type=\"checkbox\"` and `role=\"checkbox\"`, not
  `role=\"switch\"`. Screen readers announce it as a checkbox.
- **`aria-checked`** — mirrors `checked`.
- **`aria-invalid`** — set when `errorText` is present.
- **`aria-required`** — mirrors `required`.

### Screen reader behavior

Announces label and checked state as a checkbox. Consider helper text content
in the label area for critical context.

### Focus management

Focus remains on the input after toggle. Dependent fields below receive focus
only when the user tabs forward.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — track on/off and error states use action tokens.
- **2.1.1 Keyboard** — operable with Space and Tab.
- **4.1.2 Name, Role, Value** — name from label; state from `aria-checked`.
