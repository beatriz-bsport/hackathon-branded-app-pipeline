## Overview

Pagination navigates paged data sets — members, transactions, templates. It shows
current page, next/previous controls, and handles large totals (including 1000+ items).
Embed at the bottom of [List](/components/list) or [Table](/components/table) views.

### Use cases

- **Member list footer** — page through thousands of profiles.
- **Invoice history** — finance table pagination with stable sort.
- **Audit logs** — sequential pages of immutable events.
- **Search results** — sync page index with URL query param.
- **Modal pickers** — compact pagination in selector dialogs.

## Guidelines

- **Sync with data fetch** — changing page triggers new query with offset/limit.
- **Show total when helpful** — users gauge result set size.
- **Disable during load** — prevent double page jumps while fetching.
- **Preserve sort and filters** — page changes must not reset facet state.
- **Default page size** — match API default; offer size change only if product supports it.

### Best practices

#### General

<DoDont>
  <Do caption="Reset to page 1 when filters change materially." />
  <Do caption="Scroll list header into view after page change on long pages." />
  <Do caption="Disable prev/next at boundaries instead of hiding controls." />
  <Dont caption="Infinite scroll plus pagination on the same list." />
  <Dont caption="Page numbers that do not match backend total count." />
  <Dont caption="Pagination on sets smaller than one page — hide control." />
</DoDont>

### Behaviors

#### Persistence

Page index should live in URL or store for back-navigation recovery.

### Edge cases

- **More than 1000 items** — formatting and abbreviated totals per story behavior.
- **Empty page after delete** — jump to last valid page when current becomes empty.

## Accessibility

### ARIA roles & attributes

Nav region with `aria-label` "Pagination"; current page indicated programmatically.

### Screen reader behavior

Announce new page content when list region updates (polite live region optional).

### Focus management

Optional: move focus to list heading after page change.

### WCAG criteria

- **2.1.1 Keyboard** — change pages without pointer.
- **4.1.2 Name, Role, Value** — buttons name destination (Next page).
