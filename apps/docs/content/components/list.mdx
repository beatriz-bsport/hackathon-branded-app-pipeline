## Overview

Standard Back Office pattern for scannable collections. On list pages, wrap the
page in [List layout](/components/list-layout) and render a `List` of
[List item](/components/list-item) rows inside `ListLayout.Content`. Each row
aligns primary content on the left and secondary metadata or actions on the
right. Use an index [Table](/components/table) when records carry enough extra
information to show across columns — see
[Use of tables and lists](/patterns/tables-and-lists).

### Use cases

- **Scannable stack** — one primary identifier per row; users read down the list.
- **Left-right rows** — title and media on the left; status, chips, or actions on the right.
- **Row navigation** — rows link to a detail view, drawer, or modal.
- **Bulk selection** — checkbox selection with optional header select-all.

## Guidelines

### Page composition

- **`ListLayout.Header`** — page title, breadcrumbs, and primary actions (create, export).
- **`ListLayout.Content`** — scrollable area; place `List` here.
- **`List` `header` prop** — optional section label within the list (group title, select-all when bulk-selecting).

<DoDont>
  <Dont caption="Index table disguised as a list — use Table when rows need several attributes in columns." />
  <Dont caption="More than three inline row actions — push extras to overflow menu; one on mobile." />

### Behaviors

#### Persistence

Scroll position and selection typically owned by parent route and store.

#### Responsiveness

Rows stack content; compact mode reduces avatar and description density.

### Edge cases

- **Long descriptions** — truncate with tooltip on second line.
- **Controlled checkboxes** — parent must sync select-all indeterminate state.

## Accessibility

### ARIA roles & attributes

List uses semantic `ul`/`li`; checkboxes associate with row labels.

### Screen reader behavior

Announce list size changes when filters apply; bulk selection updates group label.

### Focus management

Opening row link navigates; modal actions return focus per dialog pattern.

### WCAG criteria

- **2.1.1 Keyboard** — row actions and selection operable.
- **4.1.2 Name, Role, Value** — row name from title text.
