## Overview

Typography is what makes content scannable and readable. Kaizen separates
**titles** (structure and hierarchy) from **body** text (reading flow), then
layers semantic **color** and **weight** on top through the `Title` and `Body`
components.

### Font family

Kaizen uses the **system font stack** that ships with each device. That avoids
downloading web fonts and keeps rendering native to the OS.

```css
font-family:
  ui-sans-serif,
  system-ui,
  -apple-system,
  "Segoe UI",
  Roboto,
  "Helvetica Neue",
  Arial,
  sans-serif;
```

Neither `Title` nor `Body` sets `font-family` — they inherit this stack from
global styles.

### How to compose text

Prefer **`Title`** and **`Body`** in new Back Office screens. They bind the
correct size, line height, and semantic colour tokens for you.

Inside Kaizen primitives, you will also see **utility classes** such as
`text-body-md`, `leading-sm`, and `font-strong`. That pattern is acceptable
when a component needs tight control (list rows, form controls, chips) or when
`Body`/`Title` wrappers would add unnecessary DOM nodes. Do not invent ad-hoc
font sizes — stay on the token-backed scale.

<Callout type="info" title="Body default vs dense UI">
  **`body / lg`** (`1rem` / **16px**) is the default for `Body` — readable
  prose, descriptions, and multi-line copy. Use **`body / md`** (`0.875rem` /
  **14px**) in tables, forms, buttons, and other dense surfaces.
</Callout>

## Type scale

Kaizen uses a **role-based** scale, not a single numeric ladder. Titles map to
heading semantics; body sizes map to reading density; display sizes are for
hero moments only.

### Title

Titles separate sections of content. Size is chosen through **`htmlVariant`**
(`h1`–`h5`) — you cannot pick a title token independently of the heading level.

### Body

Body styles are for multi-line copy, labels, and inline text. Render as `p` or
`span` through the **`Body`** component. When `size` is set, `Body` also applies
**`space-y-*`** between direct block children for vertical rhythm.

  <Do caption="Use Body size=md (14px) for tables, forms, and dense layouts." />
  <Dont caption="Use bold weights excessively — it disrupts flow and makes paragraphs harder to scan." />
  <Dont caption="Mix too many body sizes inside one section; it creates visual clutter." />
</DoDont>

### Display

Display tokens are reserved for hero or marketing moments — not for back-office
dense UI. They are **not** wired to `Title` `htmlVariant` values.

### Full scale reference

| Token                  | Size             | Kaizen usage                                                               |
| ---------------------- | ---------------- | -------------------------------------------------------------------------- |
| `font.size.display-lg` | 5.375rem (86px)  | Hero / marketing only                                                      |
| `font.size.display-sm` | 2.5rem (40px)    | Secondary hero headings                                                    |
| `font.size.title-xl`   | 1.75rem (28px)   | `Title` `htmlVariant="h1"` — page title, one per view                      |
| `font.size.title-lg`   | 1.5rem (24px)    | `Title` `htmlVariant="h2"` — major page sections                           |
| `font.size.title-md`   | 1.25rem (20px)   | `Title` `htmlVariant="h3"` — subsections                                   |
| `font.size.title-sm`   | 1.1rem (~17.6px) | `Title` `htmlVariant="h4"` — cards, drawers, modals                        |
| `font.size.title-xs`   | 1rem (16px)      | `Title` `htmlVariant="h5"` — nested labels inside modals and dense layouts |
| `font.size.body-lg`    | 1rem (16px)      | `Body` `size="lg"` — **default** for body copy                             |
| `font.size.body-md`    | 0.875rem (14px)  | `Body` `size="md"` — dense UI (tables, forms, labels)                      |
| `font.size.body-sm`    | 0.75rem (12px)   | `Body` `size="sm"` — captions, metadata                                    |
| `font.size.body-xs`    | 0.625rem (10px)  | Utility `text-body-xs` — badges, avatars (no `Body` size)                  |

## Components

### Title

| Prop          | Values                                                                                                    | Default   | Notes                                                     |
| ------------- | --------------------------------------------------------------------------------------------------------- | --------- | --------------------------------------------------------- |
| `htmlVariant` | `h1`–`h5`                                                                                                 | required  | Bundles size **and** semantic heading level               |
| `color`       | `default`, `weak`, `weaker`, `info`, `positive`, `critical`, `warning`, `onstrong`, `disabled`, `inherit` | `inherit` | Set `default` explicitly on page titles                   |
| `weight`      | `weaker`, `weak`, `strong`, `stronger`                                                                    | none      | No default — use `strong` or `stronger` for page headings |

`Title` does **not** support the `main` colour (interactive text belongs on
`Body` or `Link`).

### Body

| Prop          | Values                                                                                                            | Default   | Notes                                                                                               |
| ------------- | ----------------------------------------------------------------------------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------- |
| `size`        | `display`, `xl`, `lg`, `md`, `sm`                                                                                 | none      | Default to `lg` for body copy; use `md` in dense UI. `display` / `xl` are larger component variants |
| `htmlVariant` | `p`, `span`                                                                                                       | `p`       | Use `span` inside tables and inline labels                                                          |
| `color`       | `default`, `main`, `weak`, `weaker`, `info`, `positive`, `critical`, `warning`, `onstrong`, `disabled`, `inherit` | `default` | `main` for links and interactive inline text                                                        |
| `weight`      | `weaker`, `weak`, `strong`, `stronger`                                                                            | none      | Optional emphasis                                                                                   |

There is **no `Body size="xs"`** — use the `text-body-xs` utility where space
is extremely tight (avatars, chips).

### Font weight

Kaizen exposes four weight tokens. Map them through `Title` / `Body` `weight`
props — not arbitrary `font-weight` values. Neither component sets a default
weight; follow the conventions below.

| Token                  | Value | Use                                  |
| ---------------------- | ----- | ------------------------------------ |
| `font.weight.weaker`   | 300   | De-emphasised supporting text        |
| `font.weight.weak`     | 400   | Default reading weight               |
| `font.weight.strong`   | 500   | Semi-bold headings, callout emphasis |
| `font.weight.stronger` | 600   | Page headings, strong emphasis       |

### Text colour

Semantic text colours live on **`onsurface-*`** tokens — not raw palette hexes.
Use them through component `color` props.

| Role                  | `Title`                                   | `Body`                    | When to use                                              |
| --------------------- | ----------------------------------------- | ------------------------- | -------------------------------------------------------- |
| Primary               | `default`                                 | `default`                 | Main copy on standard surfaces                           |
| De-emphasis           | `weak`, `weaker`                          | `weak`, `weaker`          | Secondary labels, metadata, hints                        |
| On strong backgrounds | `onstrong`                                | `onstrong`                | Text on filled or inverted surfaces                      |
| Interactive           | —                                         | `main`                    | Links and interactive inline text                        |
| Disabled              | `opacity-sm` on default                   | `text-onsurface-disabled` | Non-interactive state                                    |
| Status                | `info`, `positive`, `critical`, `warning` | same                      | Status copy inside components — use sparingly in layouts |
| Inherit               | `inherit` (default)                       | `inherit`                 | Nested inside another text block                         |

Page and card titles should use **`color="default"`** on **`onsurface-default`**
for maximum contrast. See [Color](/foundations/color) for the underlying
palette.

## Guidelines

### Page hierarchy

Each page gets **one `h1`** — the page title (`title / xl`). Step down from
there for sections and nested surfaces.

| Surface                | Title                             | Weight                 | Colour    |
| ---------------------- | --------------------------------- | ---------------------- | --------- |
| Page title             | `htmlVariant="h1"` (`title / xl`) | `strong` or `stronger` | `default` |
| Page section           | `htmlVariant="h2"` (`title / lg`) | `strong`               | `default` |
| Detail drawer record   | `htmlVariant="h2"` (`title / lg`) | `strong` or `stronger` | `default` |
| Subsection             | `htmlVariant="h3"` (`title / md`) | `strong`               | `default` |
| Modal or Alert title   | `htmlVariant="h4"` (`title / sm`) | `stronger`             | `default` |
| Card or drawer section | `htmlVariant="h4"` (`title / sm`) | `strong`               | `default` |

Use real heading levels — don't skip from `h2` to `h4` for styling alone.

### Tables and dense UI

Tables are a common typography surface in the Back Office:

| Element            | Pattern                                                 |
| ------------------ | ------------------------------------------------------- |
| Cell text          | `Body htmlVariant="span" size="md"` — 14px dense size   |
| Column headers     | `Body htmlVariant="span"` inside header cells           |
| List row primary   | Often `text-body-lg` utility in compact list components |
| List row secondary | `text-body-md` with `text-onsurface-weak`               |

Prefer `Body size="md"` for new table and form work. See
[Tables and lists](/patterns/tables-and-lists) for layout patterns.

### Utility classes

When `Title` / `Body` wrappers are impractical, compose from token utilities:

```tsx
<span className="text-body-md leading-sm text-onsurface-weak">
  Secondary label
</span>
```

Common combinations: `text-title-sm font-strong`, `text-body-md leading-sm`,
`text-body-sm text-onsurface-weak`. Never hard-code pixel sizes or hex colours.

### Sentence case

Use **sentence case** for headings, buttons, and labels — not title case.
Sentence case reads faster in dense back-office screens.

<DoDont>
  <Do caption='Write "Member details" not "Member Details".' />
  <Dont caption="Change heading weights to lighter values — it reduces readability and contrast." />
  <Dont caption="Make headings heavier than the scale defines — it breaks Kaizen's visual rhythm." />
</DoDont>

### Line length

For long-form reading (`Body size="lg"`), aim for **45–75 characters** per line.
In dense layouts (tables, side panels), prioritise scannability over line length —
use `md` or `sm` and let the container width dictate wrapping.

### Accessibility

- Keep text contrast at WCAG **AA** minimum against its background.
- Use real heading levels (`h1`–`h5`) via `Title` — don't skip levels for styling.
- Prefer semantic `Body` / `Title` colours over hard-coded hex values.
- Don't rely on colour alone to communicate meaning.
