## Overview

Stepper (`ModalStepper`) guides users through a **multi-step process inside a modal**
— create pass, checkout configuration, onboarding setup. Each step has its own
content and validation; footer navigation moves Back, Next, or Submit on the final step.

### Use cases

- **Create buyable** — details → pricing → visibility steps.
- **Payment flow** — review → pay → confirmation in financial modals.
- **Import wizard** — upload → map columns → confirm.
- **Onboarding** — studio setup checkpoints.
- **Destructive multi-confirm** — critical action step with explicit acknowledgment.

## Guidelines

<Callout type="warning" title="Caution">

More than two stacked modals usually means the flow belongs on a page — stepper should not nest inside another modal without review.

</Callout>

<DoDont>
  <Do caption="Name each step in the header so users know what is next." />
  <Do caption="Persist draft answers when users go Back — do not wipe fields." />
  <Do caption="Use WithValidation story patterns before enabling Next." />
  <Dont caption="Optional steps hidden without indicator in the step list." />
  <Dont caption="Submit on intermediate steps that still need review." />
  <Dont caption="Stepper for single-field edits — use simple Modal." />
  <Do caption="Three to five steps — more steps suggest a full-page wizard instead." />
  <Do caption="Validate per step — block Next until current step schema passes." />
  <Do caption="Progress visible — step indicator in header shows position." />
  <Do caption="Critical final step — use critical footer styling for irreversible actions." />
  <Do caption="Escape and close — confirm data loss when dirty fields exist." />
</DoDont>

### Behaviors

#### Dismissal

Close icon and escape respect `open` controlled prop; confirm if dirty.

#### Action button

Next advances after validation; final step submits primary action.

#### Persistence

Step index and field state owned by parent; remount resets unless preserved.

### Edge cases

- **Validation failure** — focus first invalid field on Next.
- **Async submit** — disable footer while mutation pending.

### Screen reader behavior

Announce step changes when index updates (polite live region optional).

### Focus management

Focus modal on open; move to first field or heading per step.

### WCAG criteria

- **2.1.1 Keyboard** — full flow without pointer.
- **3.3.1 Error Identification** — step validation errors described.
- **4.1.2 Name, Role, Value** — dialog labeled.
