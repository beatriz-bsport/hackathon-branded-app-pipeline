## Overview

List is the standard Studio Manager collection pattern — header with title and
actions, scrollable rows built from [List item](/components/list-item), pagination,
loading and empty states. Use it for members, templates, buyables, and any
non-tabular collection where row layout beats [Table](/components/table).

### Use cases

- **Member directory** — avatar, name, chips, row actions.
- **Email templates** — title, description, overflow menu per row.
- **Buyable picker** — price and chips in checkout modals.
- **Bulk operations** — checkbox selection with header select-all.
- **Empty and search** — dedicated empty states for zero data vs zero results.

## Guidelines

- **Header actions right** — primary create/export in list header, not per row only.
- **Pagination** — use built-in pagination or [Pagination](/components/pagination) for long sets.
- **Row actions** — limit to one primary + overflow menu for the rest.
- **Loading** — show [Loader](/components/loader) in content area, not per row.
- **Link rows** — `link` prop for navigable rows; buttons for in-row actions.

### Behaviors

#### Persistence

Scroll position and selection typically owned by parent route and store.

#### Responsiveness

Rows stack content; compact mode reduces avatar and description density.

### Edge cases

- **Long descriptions** — wrap or truncate with tooltip on second line.
- **Controlled checkboxes** — parent must sync select-all indeterminate state.

## Accessibility

### ARIA roles & attributes

List uses semantic `ul`/`li`; checkboxes associate with row labels.

### Screen reader behavior

Announce list size changes when filters apply; bulk selection updates group label.

### Focus management

Opening row link navigates; modal actions return focus per dialog pattern.

### WCAG criteria

- **2.1.1 Keyboard** — row actions and selection operable.
- **4.1.2 Name, Role, Value** — row name from title text.
