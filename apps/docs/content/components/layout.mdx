## Overview

Layout in Kaizen docs refers to the **page shell composables** that frame Studio
Manager views — not a single `Layout` primitive. Use [List layout](/components/list-layout)
for collection pages, [Details layout](/components/details-layout) for master-detail,
and [Header layout](/components/header-layout) for title and action bars.

### Use cases

- **Standard list page** — `ListLayout` + [List](/components/list) + filters.
- **Record detail** — `DetailsLayout` with panel for related entities.
- **Settings form page** — `HeaderLayout` + form sections without side panel.
- **Federated SM apps** — each micro-frontend exports content into shell slots.
- **Drawer complement** — list layout with [Detail drawer](/components/detail-drawer) on narrow widths.

## Guidelines

<DoDont>
  <Do caption="Use ListLayout when the primary task is browsing a collection." />
  <Do caption="Use DetailsLayout when users edit one record with related side context." />
  <Do caption="Keep page title in HeaderLayout synchronized with document title." />
  <Dont caption="Custom page padding that fights layout gutters — use layout slots." />
  <Dont caption="Multiple competing headers from layout and ad-hoc Title stacks." />
  <Dont caption="Details panel for primary form fields — main content owns the form." />
  <Do caption="Pick shell by job — list vs detail vs settings, not one generic wrapper." />
  <Do caption="Header actions consistent — primary action top-right per Header layout spec." />
  <Do caption="Panel optional — Details layout panel toggles for secondary context." />
  <Do caption="Respect federation bridge — local dev injects navigation sidebar via `dev:watch`." />
  <Dont caption="Do not nest shells — one layout component per route root." />
</DoDont>
