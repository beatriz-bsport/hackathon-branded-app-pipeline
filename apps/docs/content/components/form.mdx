## Overview

Form documentation covers how Studio Manager wires **@bsport/form** (and related
schemas) to Kaizen inputs — [Text field](/components/text-field), [Select](/components/select),
business `Form*` fields, and submit/error handling. There is no single `Form`
primitive; composition happens in app and business component layers.

### Use cases

- **Create pass wizard** — zod schema + FormTextField + FormPriceField.
- **Member edit drawer** — validate email and phone before PATCH.
- **Settings page** — single form with section headings and save bar.
- **Modal forms** — short schema inside [Modal](/components/modal) footer submit.
- **Multi-step** — [Stepper](/components/stepper) with per-step schema validation.

## Guidelines

See [Shared form guidelines](/components/shared-form-guidelines) for cross-field rules.

<DoDont>
  <Do caption="Reuse business Form* components before wiring primitives manually." />
  <Do caption="Match validation copy to Label text for the same field." />
  <Do caption="Reset dirty state after successful save and show Toast confirmation." />
  <Dont caption="Browser alert() for validation — use inline field errors." />
  <Dont caption="Submitting untouched optional fields that overwrite null with empty string unintentionally." />
  <Dont caption="Mixing uncontrolled and controlled fields in one form without documentation." />
  <Do caption="Schema is source of truth — zod (or equivalent) drives validation messages." />
  <Do caption="Field components bind state — use `Form*` wrappers instead of raw inputs in SM apps." />
  <Do caption="Errors at field — show below control; form-level summary only for non-field errors." />
  <Do caption="Disable submit while invalid — or validate on submit with focus first error." />
  <Do caption="i18n — user strings through translation namespaces per app." />
</DoDont>

### Props

Field-level props documented on each input component. Business form fields live under
`packages/design-system/kaizen/business/src/components/form/`.

### Behaviors

#### Persistence

Dirty state local until submit; optimistic updates only when API pattern supports.

### Edge cases

- **Server validation errors** — map API field errors onto form fields.
- **Partial save** — split schemas per step in stepper flows.

## Accessibility

### ARIA roles & attributes

Associate errors via `aria-describedby` and `aria-invalid` on invalid fields.

### Keyboard navigation

  keyboard={[

### Screen reader behavior

Announce field errors when they appear (live region or focus move to first error).

### Focus management

On submit failure, focus first invalid field.

### WCAG criteria

- **3.3.1 Error Identification** — describe errors in text.
- **3.3.2 Labels or Instructions** — every field labeled.
- **4.1.2 Name, Role, Value** — invalid state exposed.
