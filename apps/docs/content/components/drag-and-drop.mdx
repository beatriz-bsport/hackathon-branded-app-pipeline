## Overview

Drag and drop provides column-based boards where users drag cards between categories —
task status, pipeline stages, or grouping workflows. It complements [Sortable list](/components/sortable-list)
for two-dimensional moves rather than linear reorder.

### Use cases

- **Internal task boards** — move items between In progress and Done columns.
- **Lead pipeline** — sales stages in CRM-style admin tools.
- **Content staging** — draft vs published groupings.
- **Category assignment** — drag activities into schedule groups.
- **Workshop planning** — optional admin layouts (not member-facing mobile).

## Guidelines

- **Column titles visible** — each drop zone labeled.
- **Empty columns** — show drop target affordance when column has zero items.
- **Persist on drop** — API update with optimistic UI and error toast on failure.
- **Accessible variant** — use accessible story patterns; do not rely on drag alone.
- **Not for long lists** — paginated tables need different interaction models.

### Best practices

#### General

<DoDont>
  <Do caption="Use AccessibleDragAndDrop patterns when shipping to keyboard-only users." />

  <Do caption="Limit column count to what fits without horizontal scroll on laptop." />
  <Dont caption="Drag-and-drop as the only path to change critical billing state." />
  <Dont caption="Tiny drag handles on mobile breakpoints without alternative UI." />

### Behaviors

#### Persistence

Parent updates item `category` on drop; rollback on API error.

### Edge cases

- **Drag cancelled** — item snaps back to origin column.
- **Same column reorder** — may delegate to sortable within column if supported.

## Accessibility

### Screen reader behavior

Announce column changes when keyboard move completes.

### Focus management

Focus follows moved item when using keyboard alternatives.

### WCAG criteria

- **2.1.1 Keyboard** — accessible variant required for compliance-sensitive flows.
- **4.1.2 Name, Role, Value** — columns and items named.
