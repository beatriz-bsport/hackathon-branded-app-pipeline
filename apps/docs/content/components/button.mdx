## Overview

The Button is a core interactive primitive in Kaizen that triggers an action or
navigates the user to a new context. It appears in forms, modals, dialogs, and
throughout the Kaizen back-office interface to communicate available actions
clearly. Buttons communicate hierarchy through three intents — `call-to-action`,
`default`, and `flat` — and adapt to different tonal contexts via the `color`
and `intent` props.

### Use cases

- **Primary actions:** Use `intent="call-to-action"` with `color="main"` for
  the single most important action on a page or modal (e.g. "Save", "Confirm",
  "Create").
- **Secondary action:** Use `intent="default"` for supporting actions that sit
  alongside a primary button (e.g. "Cancel", "Edit").
- **Subtle / tertiary action:** Use `intent="flat"` for low-emphasis actions
  that should not compete visually with surrounding content (e.g. inline row
  actions, auxiliary links).
- **Destructive action:** Use `color="critical"` combined with any intent to
  signal an irreversible or destructive operation (e.g. "Delete member",
  "Remove plan").
- **Icon-only action:** Use `kind="icon-button"` with the `icon` prop when a
  label would create clutter in dense UIs like headers or table rows — always
  pair with a tooltip.

### Content rules

Keep labels short, verb-first, and specific to the outcome — not the mechanism
("Save changes", not "Submit form"). Use sentence case. Avoid jargon unless the
audience expects it.

### Common uses

**Form submission** — `intent="call-to-action"`, `color="main"`, `size="md"`,
`loading` bound to submit state.

> "Save changes"

**Destructive row action** — `intent="flat"`, `color="critical"`,
`iconLeft="trash-01"`.

> "Delete"

**Navigation to detail** — `intent="default"`, `iconRight="arrow-right"`,
`size="md"`.

> "View details"

**Cancel / dismiss** — `intent="default"`, `color="main"`, no icons.

> "Cancel"

### Buttons vs links

A button _does something_; a link _goes somewhere_. Use [Link](/components/link)
when navigation is the primary outcome. A button may trigger navigation as a side
effect (e.g. save then redirect), but the label should still describe the action
("Save and continue"), not the destination.

### Behaviors

#### Loading state

When `loading=true`, the button renders a spinner in place of the leading icon,
sets `aria-busy`, and keeps its layout stable. The component does not set
`disabled` automatically — pass `disabled` with `loading` to prevent repeat
submissions. Remove both once the async operation completes or errors.

#### Disabled state

When `disabled=true`, the button is visually de-emphasized and does not respond
to pointer or keyboard events. Do not use disabled as a replacement for
conditional visibility — prefer hiding the action when it is permanently
unavailable in context.

#### Icon placement

`iconLeft` is preferred for icons that describe the action type (e.g. `plus`
before "Add member"). `iconRight` is preferred for directional or navigation
icons (e.g. `arrow-right`, `chevron-right`, `link-external-02`). Avoid using
both simultaneously unless both icons carry distinct meaning.

### Edge cases

#### Label is very long

The visible label truncates with an ellipsis when space is tight (`truncate` on
the label span). Prefer shorter copy; use `fullWidth` or a wider container when
the full label must stay readable.

#### Both iconLeft and iconRight set

Renders both icons flanking the label. Avoid this combination unless the icons
serve clearly distinct roles.

#### loading=true + disabled=true

Loading state takes visual precedence; the button remains non-interactive in
both cases.

#### kind="icon-button" + label prop

The `label` prop is ignored visually but should still be provided to enable
accessible aria-label derivation.

#### color="onstrong"

Intended for use only on strong-colored backgrounds.

#### color="selected"

Represents a toggled-on or active state. Use with ToggleButton patterns rather
than standalone actions.

## Accessibility

### ARIA roles & attributes

The root element is a native `<button>` with `role="button"`. Kaizen sets the
following automatically:

- `aria-label` — derived from `label` for `kind="icon-button"`; for default
  buttons, uses `aria-label` from props when provided, otherwise `label`.
- `aria-busy="true"` while `loading=true`.
- `aria-disabled="true"` when the native `disabled` attribute is set.

Icons are decorative in default buttons when a visible label is present — they
are not exposed as separate accessible names. For `kind="icon-button"`, the
`label` prop is required and becomes the sole accessible name.

### Screen reader behavior

On focus, screen readers announce the accessible name (`aria-label` or visible
`label`) and role ("button"). When `loading=true`, `aria-busy` signals that an
action is in progress — pair with a visible loader so sighted users get the
same feedback.

For icon-only buttons, never rely on the icon alone — always provide a
descriptive `label` and wrap the control in a `Tooltip` so the action is
discoverable for sighted users too.

### Focus management

Focus stays on the button when activated — there is no focus trap. The component
uses Kaizen focus-ring styles on keyboard focus (`:focus-visible`). When
`disabled` or non-interactive during loading, the button is removed from the tab
order only if you pass the native `disabled` attribute; set `disabled` alongside
`loading` for async actions you want to block until completion.

### WCAG criteria

- **1.4.3 Contrast (Minimum)** — intent and color pairings meet token contrast
  ratios; avoid placing `color="onstrong"` on non-strong backgrounds.
- **2.1.1 Keyboard** — fully operable with Tab, Enter, and Space.
- **4.1.2 Name, Role, Value** — name comes from `label` / `aria-label`; role and
  state (`aria-busy`, `aria-disabled`) are exposed on the native button.
- **4.1.3 Status Messages** — not applicable; use [Toast](/components/toast) to
  announce action outcomes after the button fires.

#### Implementation gaps

- **Loading does not block interaction** — `loading=true` sets `aria-busy` only;
  consumers must pass `disabled` to prevent double submission.
- **Redundant `aria-label` on default buttons** — When `kind="default"` and a
  visible label is rendered, `aria-label` is still set to the same string. Screen
  readers should rely on the visible text; the duplicate attribute is unnecessary
  and can cause inconsistent announcements across browsers.
- **`aria-disabled` ignores loading** — `aria-disabled` is tied to the native
  `disabled` prop only, not `loading`. Accessibility docs recommend pairing
  both; the component does not mirror loading into `aria-disabled`.

#### Design or API debt

- **Props table types are incomplete** — `react-docgen-typescript` cannot parse
  Button's discriminated-union props; generated types show as `unknown` until
  the extract pipeline or overrides are improved.
