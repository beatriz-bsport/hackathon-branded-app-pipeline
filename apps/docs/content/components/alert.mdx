## Overview

Alerts communicate feedback on user actions, system events, or contextual information that requires attention.

Alerts are used to inform users about important information, changes in status, or required actions. They effectively communicate feedback on user actions, system events, or contextual information, ensuring users are aware of key messages or warnings within the application .Communicate critical information that requires user attention (e.g. warnings, errors, system messages).

### Use cases

- _Success confirmations:_ Show success messages for important operations like saves or sync.
- _Warnings_: Alert users of potential issues like missing configuration or feature limitations
- _Error messages:_ Display prominent error messages that require user's attention

#### Content

##### 1. Informational alert (no action)

Use when you need to surface a neutral message with no user action required. Set `has-actions: false`, `is-clearable: false`, `color: info`.

> _Example: "Your account is set to read-only mode. Contact your admin for access changes."_

##### 2. Success confirmation with dismiss

Use after a user successfully completes an operation. Set `color: positive`, `is-clearable: true`, `has-actions: false`.

> Example: "Changes saved. Your settings have been updated successfully."

##### 3. Warning with action

Use when a potential issue exists but the user can resolve it. Set `color: warning`, `has-actions: true`, `buttonLabel: "Review"`.

> Example: "Paypal is not included in this payout list. Please check Paypal page for more details."

##### 4. Critical error, non-dismissible

Use for blocking errors that require immediate resolution. Set `color: critical`, `is-clearable: false`, `has-actions: true`, `buttonLabel: "Retry"`.

> Example: "Payment processing failed. Please check your billing details and try again."

### Behavior

##### Action button

When `has-actions` is `true`, an inline button is rendered using the `buttonLabel` prop. Clicking it fires `onButtonClick`. If no label or handler is provided, the button should not be rendered regardless of the prop value.

##### Persistence

Alerts are persistent by default — they do not auto-dismiss. Auto-dismiss behavior (e.g. after a timeout) must be implemented at the product level if needed. For transient feedback, use the Toast component instead.

### Edge cases

##### Long body text

Body text wraps naturally inside the container. Avoid exceeding 4 lines of body copy — if the message is longer, consider a Modal or Panel instead.

##### No icon (left slot off)

When `has-left-slot: false`, the alert renders without a leading icon. Only use this in contexts where the color and title already communicate the severity clearly.
