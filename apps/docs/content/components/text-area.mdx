## Overview

Text area collects multi-line plain text — class descriptions, email bodies, internal
notes, and comment fields. It supports labels, helper text, error state, and
disabled/read-only modes consistent with [Text field](/components/text-field).

### Use cases

- **Class description** — public-facing copy in booking session setup.
- **Email template body** — marketing message editor alongside subject field.
- **Internal notes** — staff-only comments on member profiles.
- **Rejection reasons** — optional explanation on approval workflows.
- **JSON or code** — only when plain text is acceptable; rich text needs another editor.

## Guidelines

- **Pair with Label** — always visible label via [Label](/components/label) or `label` prop.
- **Set expectations** — helper text for character limits or formatting rules.
- **Resize thoughtfully** — default vertical resize; constrain height in dense layouts.
- **Error below field** — match single-line field error placement.
- **Not for single-line data** — names and emails belong in Text field.

#### General

### Behaviors

#### Responsiveness

Grows with content when resize allowed; parent can set `rows` or max-height.

### Edge cases

- **Very long paste** — enforce maxLength at form layer if backend limits size.
- **Disabled** — value visible but not editable; ensure contrast meets disabled tokens.

## Accessibility

### ARIA roles & attributes

Associates with label via `id`/`htmlFor`. Error text should use `aria-describedby`
when implemented in form wrappers.

### Screen reader behavior

Announces label, value, and error/description ids when wired.

### Focus management

Focus stays in field during editing.

### WCAG criteria

- **3.3.1 Error Identification** — describe validation failures.
- **3.3.2 Labels or Instructions** — visible label and helpers.
- **4.1.2 Name, Role, Value** — value updates on input.
