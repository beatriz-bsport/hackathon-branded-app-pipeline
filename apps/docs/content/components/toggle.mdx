## Overview

Toggle switches a boolean setting as soon as the user changes it — the parent
handles `onToggleChange` and typically persists or applies the new state right
away. Use it for live preferences (notifications, feature flags on a detail
page). Use [Checkbox](/components/checkbox) when the user must confirm with
Save or Submit.

## Guidelines

<DoDont>
  <Do caption="Show dependent fields only when checked, indented under the toggle row." />
  <Do caption="Revert `checked` and surface `errorText` or a toast when the API fails." />
  <Dont caption="Settings the user confirms with Save or Submit belong on Checkbox, not Toggle." />
  <Dont caption="Terms, consent, and checkout opt-ins belong on Checkbox, not Toggle." />
</DoDont>

<Callout type="warning" title="Caution">

Avoid vague labels like "Enable" without naming the setting — pair the verb with
the feature: "Online booking", "SMS reminders".

</Callout>

### Behaviors

`onToggleChange(boolean)` fires on each change. Parent owns `checked`.
`direction="end"` places the track on the right for dense settings rows.

### Known issues

- Uses `role="checkbox"`, not `role="switch"` — screen readers announce "checkbox".
- No built-in nested field slot — compose dependent fields manually.
- [KAI-583](https://linear.app/bsport/issue/KAI-583), [KAI-589](https://linear.app/bsport/issue/KAI-589)
